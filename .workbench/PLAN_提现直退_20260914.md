## 0. 老板的原话
> "除了这三个能识别到的口，其他的口进入小程序提现就直接通过，或者像刚才改之前直接生成投诉进行处理"

三个"能识别到的口" = 我们自己放出去的二维码（带场景值）/ 公众号菜单点击 / 用户主动发消息。

## 1. 前提事实（实测）
| 项 | 数值 |
|---|---|
| 近 30 天提现用户 | 34,595 人 |
| 其中"来源可识别"（在 wx_oa_messages 里有记录） | 3,506 人（10.1%） |
| 其中"完全认不出来源" | **31,089 人（89.9%）** |
| 近 30 天提现规模 | 49,889 笔 / **103.97 万元**，平均 20.84 元，最大单笔 143.79 元 |
| 余额现状 | 各商户号 BASIC 余额 1,920~10,485 元（09-12 快照） |
| 余额不足导致的退款失败 | 近 7 天 **45 笔**（"基本账户余额不足，请充值后重新发起"） |
| 提现被随机拒（通过率未达标） | 近 7 天 **1,303 笔** |

**结论：按"来源不明就直退"这个条件，实际覆盖 89.9% 的提现用户 ≈ 几乎全部。**

## 2. 判定口径
- 身份按 unionid 归并（无 unionid 退化为手机号 / 公众号 openid）
- "来源可识别" = 该用户在 wx_oa_messages 里有任意记录（菜单点击/关注/发消息/订阅事件）
- "来源不明" = 一条都没有 → 走本方案

## 3. 放行方式
### 方式一（推荐）：加一条"直退旁路"
- 提现创建时判定"来源不明" → 写 approver='来源不明直退' 的 withdrawal_records（status=0）
- 由现有批量任务（run_withdrawal_batch.py，每 3 分钟）原路退款
- 复用 whitelist_auto 必退通道的模式，只换触发条件
- **不动**：网点的 withdraw_mode、refund_approve_rate、存量卡单
- **不新建投诉工单**

### 方式二（不建议）：生成投诉工单 → 走投诉自动退款
不建议原因：① 正是 2026-09-13 刚修掉的机制（会再污染投诉数据，当晚刚清理 3,258 条假投诉）；
② 投诉数是指标；③ 该通道不检查订单是否已结束（就是那 80 笔"人还没取物就退款"的来源）。

## 4. 三个必须的安全阀
1. **退款前查商户号可用余额**，不足则排队等（不直退）——否则几小时掏空余额、失败率飙升
2. **次数/金额上限**：单笔 ≤ M 元、每人每天 ≤ N 笔
3. **订单必须已结束（已取物）才退** —— 补上 2026-09-13 发现的 80 笔漏洞

## 5. 灰度与回滚
- 灰度：先对"近 30 天无投诉 + 单笔 ≤20 元 + 每人每天 1 笔"开放 → 观察 3 天（失败率/投诉数/余额）→ 再放宽
- 回滚：旁路开关关掉即恢复原状（不涉及存量数据）

# 方案 v2（老板纠正口径后重算，2026-09-14 01:10）

## 老板的口径

## 回答老板的问题：能不能识别出"是微信账单进来的"
**不能。** 三个理由（都有数据支撑）：
1. 报文里只有 `Event / EventKey / MenuId / appid`，**没有任何"进入来源"字段**；全库 5,000+ 条里含 bill/transaction/attach 的 = 0 条
2. 已关注用户**打开公众号不产生任何事件** —— 我们连"他进过公众号"都不知道，更别说从哪进的
3. 关注事件只有**扫我们自己投的码**才带场景值（`qrscene_xxx`，全库仅 1 次），其余关注一律 EventKey 为空

所以"账单入口"**不能作为规则条件**（判不出来）。能用的可识别信号只有一个：
**"该用户从公众号点菜单进过小程序"**（`view_miniprogram` 事件 + MenuId）。

## 方案 v2 的规则
> **凡是有"从公众号点菜单进过小程序"记录的用户，提现走"直退旁路"（免审、原路立即退款）**

- 理由：这批人明确是"从公众号进来的"，但**无法区分他是账单/搜索/分享/支付后提示**哪条路来的 → 既然分不出，就一律按"从公众号来的"放行
- 影响面：**8.4% 的提现用户 / 近 30 天 89,153 元**（≈ 3,000 元/天，资金压力可控）
- **不动**网点 withdraw_mode / refund_approve_rate / 存量卡单
- **不生成投诉工单**（走 way1 直退旁路）

## 三个安全阀（同 v1）
1. 退款前查商户号可用余额，不足则排队等
2. 单笔/每日次数上限
3. 订单必须已结束（已取物）才退
