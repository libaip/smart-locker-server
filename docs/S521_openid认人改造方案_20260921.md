# S521-20260921 身份改造方案：彻底按 id 认人（小程序只看小程序 ID、公众号只看公众号 ID）

> 依据：老板 2026-09-21 决策 —— ① 存量数据彻底不管（没 openid 的老账号让用户找客服）；② 新数据统一按 id 认人；
> ③ 小程序与公众号**各自算各自的、不合并**；④ H5 跳小程序时订单上双写两边 id，但**身份不合并**；
> ⑤ 存量重复 id 行按「取最早那一行 + 告警 + 客服可人工合并」处理。
> 本方案只写文档、不动代码；等老板说「做」再按阶段施工。

---

## 一、改完之后"谁是谁"是什么样（目标态）

| 入口 | 拿什么当身份证 | 备注 |
|---|---|---|
| 微信小程序（存包/取件/我的/余额/提现/订阅） | **mp_openid**（服务端用 code 换来的） | 小程序身份只认它自己 |
| 微信公众号 H5（存包/取件/余额/提现） | **公众号 openid**（服务端 OAuth 换来的） | 公众号身份只认它自己 |
| 支付宝小程序 | **alipay_uid**（getAuthCode → /alipay/login） | 已按 S518/S519 落地 |
| 支付宝 H5 | 没有 openid → 用**付款人 uid**（回调 buyer_id）落订单；小程序侧 uid 落 alipay_mp_uid | S519 订单桥接已上线 |
| H5 跳小程序 | 订单上**同时**记公众号 openid 与小程序 openid | **只记在订单上，身份不合并** |

**手机号的新定位**：只是"联系方式"（写 `orders.user_phone`、客服找人、发短信），**不再参与任何身份判定**。
**身份唯一规则**：一个 mp_openid = 一个身份；一个公众号 openid = 一个身份；两者相交不作合并。

## 二、现状（要改的就是这些）

### 2.1 三张表 + 订单
- `users`：`id`(user_id)、`phone`、`openid`(公众号)、`mp_openid`(小程序)、`unionid`、`alipay_uid`、昵称/头像。
  **只有主键和 alipay_uid 有索引**；openid / mp_openid / unionid 上**没有唯一约束**。
- `phone_openids`：`phone` / `openid` / `mp_openid` / `gzh_openid` / `unionid` / `user_id` / `alipay_uid` / `is_frozen`。
  唯一键全是**"手机号+身份"组合**：`(phone,mp_openid)`、`(phone,openid)`、`(phone,unionid)` → **手机号被焊进主键**。
- `user_balances`（钱包）：`phone` **NOT NULL**；`balance`；唯一键 `(phone)`(UN 空时)、`(phone,mp_openid)`、`(phone,unionid)`，另有 `openid` 唯一索引。
- `orders`：`user_phone`、`openid`、`mp_openid`、`unionid`、`user_id`（"这单算谁的"）。

### 2.2 认人的真实顺序（线上代码）
- `resolve_user_identity()`（helpers.py:1618，总入口）：**UN → mp_openid → openid** 三个强键；`user_id` 直接给定则优先；
  强键查不到 → **手机号兜底**；命中多行且 UN 不一致 → **判 ambiguous、拒绝自动选择**（S419 之后加的保护）。
- `_resolve_order_identity()`（routes/user.py:268）：**手机号打头**（`phone_openid_rows(phone=…)`），查到 1 行就补 openid/UN 到订单，
  再按手机号 upsert 回对照表/钱包表。
- 写库：`upsert_phone_openid_row()` / `upsert_user_balance_row()` **开头就是 `if not phone: return None`**（没手机号连行都不落）。
- 已有的"好样板"：**S320 新小程序**（strict：只认自己的 mp_openid、丢公众号 openid/UN、不用手机号兜底）；
  **S406 新公众号**（openid 属于当前启用公众号前缀 → 丢掉 phone/unionid 兜底、只按 openid 认人）。这两套规则要**推广到所有新数据**。

### 2.3 存量脏数据（实测，本次"不管"，但要留监控）

## 三、设计（新数据走新路，老数据一行不动）

### 3.1 新增"按 id 认人"函数（不新建表）
```
resolve_user_by_ident(cursor, kind, ident) -> user_id
  kind ∈ { mp_openid | oa_openid | alipay_uid }
  1) ident 去空格；空 / 长度不在合法区间（openid 28 位、alipay_uid 16-32）→ 直接返回 0
     （**决不做任何兜底查询** —— S419 就是空串变通配符）
  2) 取该身份的咨询锁：SELECT pg_advisory_xact_lock(hashtext('ident:'||kind||':'||ident))
     目的：并发下同一身份不会各建一行（不加唯一索引也能防重复建行）
  3) SELECT id FROM users WHERE <对应列> = %s ORDER BY id
       命中 1 行   -> 用它
       命中多行   -> 取最早那行(id 最小) + logger.warning + 记一条告警（客服可人工合并）
       命中 0 行   -> INSERT INTO users (<对应列>, phone) VALUES (%s, '') RETURNING id
  4) 返回 user_id
```
- 老 `resolve_user_identity()` **保留不删**（开关关掉即回退）。
- 钱包/订单落行统一以这个 user_id 为准；**新行 phone 允许为空**。

### 3.2 开关（关键：出问题一秒回退，不用改代码）
`system_settings` 新增 `identity_strict_mode`，取值：
- `off`（默认，等于现在的老逻辑）
- `new_order`：**只有新建订单**走新函数
- `all`：查询/提现/退款归属等也走新函数

### 3.3 数据层（只加不删）
1. `ALTER TABLE user_balances ALTER COLUMN phone DROP NOT NULL`（允许无手机号建钱包行）
2. （阶段 5 才做，且需先确认无新增重复）`users` 加 partial unique：`(mp_openid) WHERE mp_openid<>''`、`(openid) WHERE openid<>''`
3. 存量行、老索引**一律不动**

### 3.4 各调用点怎么改
| 位置 | 改法 |
|---|---|
| `store_init`（建单） | 身份取本次请求的 mp_openid / 公众号 openid / alipay_uid；`user_id` 由 `resolve_user_by_ident` 得到；`user_phone` 只存联系方式 |
| `_resolve_order_identity` | 不再"手机号打头"；改为"传入 id 优先"，查不到再走老逻辑（过渡期） |
| `/user/link-mp-openid`（H5→小程序） | **订单上双写** openid + mp_openid；**删掉"把 mp_openid 合并进 users 同一行"的写回**（保留订单双写） |
| `/user/info`、订单列表、取件、余额、提现、退款归属校验 | 一律用 user_id（由 id 认人得到），不再按手机号查 |
| 通知发送（公众号模板消息/小程序订阅） | openid 从**订单/身份**取，不再按手机号找 |
| 写库辅助函数 | 新增"按 id 落行"分支；去掉 `if not phone: return None` 的硬门槛 |

## 五、对账脚本（每 30 分钟自动跑，异常进中控告警）
1. **身份一致性**：近 30 分钟新订单，其 `user_id` 对应的 `users` 行是否包含订单上的 openid/mp_openid（不一致=串了）
2. **新增重复**：近 30 分钟是否出现"同一 mp_openid/公众号 openid 多行"（新增重复必须为 0）
3. **钱分散**：同一 openid 是否出现在多行钱包（余额被拆散）
4. **无 id 新行**：新建 users 行里"三种 id 全空"的数量（应恒为 0）
5. 输出到 `alarms`（中控红点）+ 日志，附可点开的订单号/身份样例

## 六、客服工具（中控，只读）
凭 **手机号 / 订单号 / openid** 查：老账行、钱包余额、相关订单；**只读、不能改钱**。用于"那 1,798 个无 openid 老账号"的人工处理。
