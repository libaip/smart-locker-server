### 2. 后端是「多账号」架构，切换机制很完善

`wx_config.py` 的设计原则（原文）：

> 1) 配置在库里，业务每次「实时读」→ 改完立刻生效
> 2) **同类账号同一时刻只有一个 is_active=1**（当前生效），其余是待命备用
> 3) `auto_disabled` = 连续失败自动停用 + 自动切备用
> 4) 读库失败 / 库为空 → 回落 DEFAULTS，保证业务永远不炸

**★ 关键：切换用的是 `set_active(account_id, probe_first=True)` —— 会先探测新号可用，不可用就不切。**

**★ 而且有 `resolve_by_appid()` / `account_id_by_openid()` —— 老号（伧置）的记录不会被删，老用户仍能被识别。**

## 四、阶段三：后端配置（我做，改数据不改代码）

| # | 改什么 | 表/位置 | 说明 |
|---|---|---|---|
| 3.1 | 更新/新增新小程序记录 | `wx_accounts` | `appid` + `secret` + `subject` + `name` |
| 3.2 | **切换生效账号** | `wx_accounts.is_active` | 用 `set_active(id, probe_first=True)`，**会先探测可用再切** |
| 3.3 | **回填 `openid_prefix`** | `wx_accounts.openid_prefix` | ★ 待首个用户登录后，从日志 `[wx_login]` 里取前缀（如 `oTxxxx`） |
| 3.4 | 新增支付渠道 | `payment_channels` | 新商户号 + `app_id` 绑新 appid + `is_active=1` |
| 3.5 | 登记订阅模板 | `wx_templates` | 3 个模板的 ID，`channel='mp'`，`account_id=新号 id` |
| 3.6 | 检查域名/入口配置 | `wx_config_items` | `h5_base`、`entry_mode`、`mp_entry_path` 等 |

> ⚠️ **3.3 是最容易漏的一步**：`openid_prefix` 是后端判断"这个 openid 属于哪个小程序"的依据。
> 不回填的话，新用户首次登录会被认成别的号。
> 后端备注里已经写了方法：**从日志 `[wx_login][新小程序]` 取前缀**。

## 六、风险点（必须知道）

| 风险 | 说明 | 缓解 |
|---|---|---|
| **★★★ 关联判定** | 新小程序的主体如果和现有 5 家有关联，**一绑定就被判"关联商户交易异常"** | 老板先确认 D2（主体干净） |
| **订阅模板要重新申请** | 微信不给跨小程序复用模板 ID | 阶段一 1.4 提前做 |
| **`openid_prefix` 忘了回填** | 新用户会被认错号 | 阶段四 4.1/4.2 必做 |
| **切换影响老用户** | `is_active` 只能有一个，切新号后默认账号变了 | 切换用 `probe_first`，且老号记录仍在，`resolve_by_appid` 能兜住 |
| **商户号绑不上** | 微信要求 appid 和 mch_id 同主体或已关联 | 阶段一 1.6 先做 |
